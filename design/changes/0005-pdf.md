# 0005: Reading PDF, as an optional extra

## Status

`proposed` (2026-11-24). Replaces D-022 ("no PDF in 0.1").

## Context

ragcourt reads Markdown, text, reStructuredText and HTML (§4.1). Many of the corpora people build RAG on
are PDFs: manuals, papers, contracts, reports. Today a folder of PDFs gives "No documents to rank", and the
tutorial says to convert them first. D-022 left PDF out because extraction changes the text (columns,
hyphenation, running headers), "which would make verbatim depend on the extractor", and said a `pdf` extra
could come with its own change record. This is that record.

## Problem

Read PDFs without weakening "gold is an exact quote found verbatim in the source" (rule 5), without a core
dependency, and without hiding what the extractor did to the text.

## Options

1. **Leave it as it is:** the user converts PDFs with a tool of their choice. Honest, and a wall for most
   first tries.
2. **`pymupdf`:** the best extraction, but AGPL: it cannot be a dependency of an Apache-2.0 tool that
   people put inside their own products.
3. **`pdfplumber`** (on `pdfminer.six`): good layout analysis, slower, two packages.
4. **`pypdf`** as the optional extra `pdf` (chosen): pure Python, BSD, widely used and actively
   maintained (its installed size and release dates are to be measured as 0002 did, before it is accepted); it meets the rule proposed in 0002 for a
   general job, and as an extra it also fits D-003 as it stands.

## Decision

`pip install 'ragcourt[pdf]'` makes `.pdf` a document type.

- **The document is the extracted text.** A PDF's `Document.text` is what `pypdf` extracts, page by page,
  pages joined by a blank line, line endings normalised, nothing else changed (no de-hyphenation, no
  header removal, no reflowing). Offsets, quotes, chunks and metrics all refer to that text, exactly as
  an HTML page's refer to its extracted text (§4.1). Gold stays verbatim: verbatim in the text ragcourt
  and every chunker under test were given.
- **What the extractor did is visible.** `ragcourt audit DOCS --show file.pdf` prints the extracted text
  with the chunk boundaries, as for any document; the audit's first lines say how many documents came from
  PDF and name the extractor and its version. `docs/` gains a short page on what to expect (columns read
  in the wrong order, words broken at line ends, a running header on every page) and says plainly: if your
  own system extracts differently, convert the PDFs with your extractor and give ragcourt the text.
- **What cannot be read is skipped with its reason**, never guessed (as §4.1 does for bad UTF-8): no text
  layer ("scanned: run OCR first"), encrypted, damaged, over 50 MB. Without the extra, each PDF in the
  folder is listed as skipped with "install 'ragcourt[pdf]' to read PDF", instead of being ignored in
  silence as today.
- **Code:** one new module `io/pdf_text.py` (`pdf_to_text(path) -> str`, importing `pypdf` inside the
  function, raising `ExtraMissing` without it), and two branches in `io/documents.py`.

## Consequences

- `pyproject.toml`: extra `pdf = ["pypdf>=5"]`, also in the dev group so the gate tests it; D-059 in
  `design/decisions.md` gives the reason; `tests/unit/test_import_boundaries.py` lists `pypdf` as optional.
- Design §1 (non-goals: scanned documents stay out), §4.1, §7.4, §17 and §18; `docs/README.md` and the new
  page; tutorial chapters 2, 18 and 20; the README's install line.
- The corpus hash is over extracted text, so a `pypdf` release that extracts differently changes the hash;
  the existing rule then keeps every question whose quote is still found (D-047) and says how many.
- A running header that repeats on every page of one PDF is not caught by `boilerplate.repeated`, which
  counts documents (§5.1). Kept as a known limit in §18; a per-page rule would be its own change.

## Risks answered

- **Gold independent of chunking / verbatim:** unchanged; see "the document is the extracted text".
- **Numbers are measured:** unchanged. A corpus whose extraction is poor will show it in the audit
  (`cut.mid_sentence`, `size.tiny`), not hide it.
- **The core imports no extra:** `pypdf` is imported only inside `pdf_to_text`.
- **Privacy:** `pypdf` reads local files and contacts nothing.
- **Security:** PDFs are untrusted input: the size cap, a page cap, and `pypdf`'s errors turned into a
  skip with a reason; no JavaScript, form or attachment in a PDF is ever run or opened.
- **Simplicity:** one file, one extra, no new configuration.
- Blame, files, generated code, layers: untouched.

## Acceptance cases (design §16)

39. **PDF is read with the extra.** A text PDF in the folder is loaded as a document whose text holds its
    sentences; `audit` runs on it and names the extractor; a question's quote is found verbatim in it.
40. **A PDF that cannot be read is said, not guessed.** Without the extra, each PDF is listed as skipped
    with the install command; a PDF with no text layer, an encrypted one and a damaged one are each skipped
    with their reason, and the other documents are still loaded.

## Tests

`tests/e2e/test_ac39_pdf_is_read.py`, `test_ac40_pdf_skipped_with_reason.py`; unit tests for
`pdf_to_text` on small PDFs kept in `tests/fixtures/` (two pages, two columns, no text layer, encrypted,
truncated); the import-boundary test. No real model is needed.

## Migration and compatibility

A folder that held PDFs beside text files: without the extra nothing changes but the new skipped lines;
with it the corpus grows, so its hash changes and the question set is extended as for any added document.

## Open questions for the owner

1. **De-hyphenation** ("docu-\nment" to "document"): off (proposed, the text stays what the extractor
   gave), or on by default?
2. Should **`.docx`** come the same way later (its own record), or stay out?
